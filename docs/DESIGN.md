# DESIGN.md — デザイン原則と画面監査

この文書は、このアプリの「見た目の約束事」を固定する場所です。新しい画面や部品を作るときは、まずここに照らしてください。約束事は3段で守ります：

1. **この文書**（原則と具体値）
2. **自動テスト**（座標・寸法・色など、数値で測れる約束は E2E で固定する）
3. **公開前の全画面監査**（残りは人の目で確かめる。手順は本書末尾と `docs/HANDOVER.md` の公開前チェックリスト）

構成は2部に分かれています。**第I部は一般論**（どの作品でも使える原則の立て方・部品カタログの形式・監査手順・自動テスト化の方針）で、後からテンプレート（pwa-template）へ一般論だけを移せるようにしてあります。**第II部はこの本固有の値**（色・寸法・世界観）です。新しい作品では第II部だけを書き換えます。

---

## 第I部 一般原則（どの作品でも使える）

### 1. 原則の立て方

- **画面ごとの独自実装を増やさない。** 新しい画面は、既存の共通部品の組み合わせで作る。画面専用のボタン・帯・表示を作りたくなったら、まず「共通部品で表せないか」を疑う。どうしても専用にするときは、この文書に理由と値を書き足してから実装する。
- **見た目の決定は1か所に集約する。** 色・寸法は CSS 変数（トークン）に置き、画面側に直値を散らさない。
- **決定は版とセットで記録する。** 見た目を変えたら、その版の変更点として `docs/HANDOVER.md` に残し、この文書の該当値も同じコミットで更新する。

### 2. 家具（全画面共通の操作要素）の原則

- 読書の主画面（本文・扉・目次など）には、**全画面で同じ帯**を持たせ、同じ操作要素を**同じ位置**に置く。位置は綴じ方向で決まる（右綴じなら左下＝進む側の操作、右下＝戻る側の操作、のように）。
- 要素の位置は**絶対配置で固定**する。片方の要素がモード等で隠れても、残った要素は動かない（flex の詰め直しで位置が変わる作りにしない）。
- タップ領域は **44px 四方以上**。ただしアイコン自体は小さく薄く描き、**背景になじませる**（輪郭が要る場合も、うっすらした縁取りと僅かな陰影に留める）。操作要素が画面の主役になってはいけない。
- 帯は画面や紙の**下端にくっつけず、少し浮かせる**（浮きの量はトークンで全画面共通に保つ）。
- 状態で出し分けるのは「有無」だけにし、位置とトーンは変えない。

### 3. 色の意味

- 色は飾りではなく**意味**で割り当てる：基調色（タイトル・主要な面）、紙色（読む面）、墨色（本文）、アクセント色（見出し・区切り・現在地の印など、意味のある場所だけ）。
- **OS やブラウザ標準の色に頼らない**（標準の青いチェック、青いリンク色など）。標準部品の見た目が世界観と合わない場合は、自前で描く。
- 警告や主要ボタンのような強い意味の色は、別の意味に流用しない。

### 4. 余白と整列の原則

- 縦書きでは、並ぶ要素（柱）の**頭（上端）を完全に揃える**。要素ごとに中央寄せすると頭がばらつくのでしない。
- 項目群の縦位置は、画面の中央ではなく**少し上気味**に置き、**下の余白を広めに取る**（本の版面の考え方）。
- 並ぶ要素の**背丈は統一**する。現在地の印（背景色）などの状態表示の面積が、内容の長さで変わらないようにする。
- 寸法は「なんとなく」ではなく実測で決める。決めた値はトークンに名前を付けて残す。

### 5. 共通部品カタログの形式

共通部品は次の形式でカタログ化し、第II部に実物を置く：

| 部品 | 役割 | 寸法・トーンの決め方 |
|---|---|---|
| （クラス名） | （何のための部品か） | （タップ領域、図柄の大きさ、色、位置の規則） |

新しい部品を足したら、このカタログにも足す。カタログに無い見た目が画面にあってはいけない。

### 6. 公開前の全画面監査（手順）

版を出すたびに、公開前に必ず1回行う：

1. 全画面のスクリーンショットを撮る（撮影スクリプトで、表紙・目次・扉・本文・メニュー・奥付＋主要な状態違い）。
2. 撮った画面を並べ、この文書の約束事と1画面ずつ照らす。観点は「崩れ・はみ出し・動作」だけでなく、**形の比率、色の意味、余白と整列、世界観との一致**まで含める。
3. 気になる寸法はピクセル実測で裏を取る（推測で済ませない）。
4. 見つけた差異は**公開前に直す**。直した内容はその版の報告に含める。直さないと決めた差異も、理由とともに報告へ残す。

### 7. 自動テスト化の方針

- **座標・寸法・色（computed style）で測れる約束は、E2E の検証として固定する。** 人の目の監査は「新しい差異の発見」、自動テストは「決めたことの回帰防止」と役割を分ける。
- **共通部品を使っているか**（全画面の帯に同じクラスの要素があるか、独自部品が混ざっていないか）は DOM 構造で検出できるので、E2E か静的チェックに寄せる。
- 逆に、世界観との一致や「なんとなく上品か」のような判断は数値化できない。無理にテスト化せず、監査（人の目）に残すと明記する。

### 8. 初回案内（ダウンロードの断り書き）の原則（v1.13.0〜）

- 配信は「初回に全部取り込む」一括方式。取り込みは Service Worker の登録と一緒に始まるため、**案内は登録より前に**出す（閉じられてから登録する）。案内より先にダウンロードが始まる作りにしない。
- 案内は表紙の上にモーダル（共通部品 `.modal`）で1回だけ出す。本文には、その本の音声の総容量をデータから動的に入れる（作品ごとに直書きしない）。閉じたら「見た」を保存し、**二度と出さない**。その端末を既に SW が制御している（＝以前の版で取り込み済み）場合も出さない。
- 文面の要点は3つに絞る：音声も一緒に届くこと／初回にまとめて取り込むので Wi-Fi 環境がおすすめなこと／一度取り込めばオフラインで読めること。ボタンは主要ボタンの色で1つだけ置く。

## 第II部 この本固有の値（『空の郵便が届くまで』）

### 1. 世界観と色

深い藍の机の上に、生成りの紙の本が載っている、という世界観で統一する。

| トークン | 値 | 意味 |
|---|---|---|
| `--indigo` / `--indigo2` | #0a1220 / （表紙の放射グラデーション） | 机（表紙側の地） |
| `--desk` / `--desk2` | #17130e 系 | 机（扉・本文側の地） |
| `--paper`（`--surface`） | #fdfaf0 | 紙（生成り） |
| `--ink`（`--text`） | #262019 | 墨（本文） |
| `--navy`（`--primary`） | #1b2a4a | 藍＝基調（題字・見出し・チェックの塗り） |
| `--gold` | #c9b87a | 金（進み具合ライン、淡い装飾） |
| `#8a6d2f` | 金茶 | 見出しラベル・柱の章番号・ノンブルなど、紙の上の控えめなアクセント |
| `--border` | #d8cfb4 | 紙の上の罫 |
| `--muted` | #6a6252 | 補足の文字 |

- チェックボックスは OS 標準の青を使わず、藍（`--indigo2` 系）で塗る自前描画（v1.12.2）。
- フォントは明朝（`--serif`）。本文の文字サイズ設定は 標準／大（1.2倍、`--font-scale`）。

### 2. 家具の具体値（本文・扉・目次で共通）

| 部品 | 役割 | 具体値 |
|---|---|---|
| `.sheet-footer` / `.page-footer` | 画面下の帯 | 高さ 44px（`--folio-band`）。中身は絶対配置で固定し、片方が隠れても動かない（v1.12.3）。帯はページ下端から `--band-lift: 10px` 浮かせる（v1.12.4。本文・扉・目次で共通。安全領域ぶんの余白とは別に、紙の中での浮きとして足す） |
| `.page-icon-btn` | 帯のアイコン（再生 ⇔・家マーク・文送り） | タップ領域 44×44px、図柄 19px。地の生成りに近い薄いトーンで、輪郭はうっすらした縁取りと僅かな陰影だけ（主張させない）。右綴じでは左下＝再生側、右下＝家マーク。左綴じでは左右を入れ替える |
| 文送り（`.sent-group`） | 本文専用：[前の文][再生/停止][次の文] | 再生の並びに同じ `.page-icon-btn` で置く。並びはメディア標準（左=前の文／中央=再生・停止／右=次の文、進むは右）で固定し、綴じ方向で反転させない（座標と図柄を E2E で固定）。図柄はメディア標準のスキップ型（三角＋棒）。耳で読むときだけ出し、目で読むでは出さない。扉・目次には付けない（v1.12.4） |
| 再生の図柄 | 本文・扉・目次（奥付は非表示のまま同じ図柄を持つ） | **スピーカー＋波紋**（線画、家マークと同じ stroke の作法）。右向き三角（▶）は右綴じの綴じ方向と競合して進む／戻るの誤読を招くため廃止し、向きを持たない音の記号にした（v1.13.1、ユーザー決定）。一時停止は二本線（❙❙、塗り）のまま |
| `.folio` | ノンブル | 帯の中央（絶対配置で紙の中央に固定）。「― N ―」体裁（目次は「― N / M ―」）。文字は金茶・小さめ |
| `.page-head` | 本文の柱（章題） | 帯の上に小さく金茶で。章題のみ（ページ数の 〇/〇 は出さない） |

- 目で読むモードでは、帯の再生アイコンだけが全画面で消え、家マークは右下のまま（v1.12.2〜）。
- 扉の下部に案内文言は置かない（v1.12.3 で削除）。
- 表紙は帯の家具を持たない代わりに、入口をモードの2ボタン（プレート型）に一本化し、バージョン表記は下部中央に置く（デバッグの5回タップもそこ）。

### 3. 画面ごとの構成

- **表紙**：地絵は生成イラスト（雨空の商店街、全面・金枠なし）に、題字・著者名・ロゴを後付けで重ねる装丁（v1.13.3 で新装丁に差し替え。旧装丁は藍地に鳥と書店のベタ塗り＋刷り込み文字）。題字は縦書き2列で上 12%／背側の余白 14%、色は地絵の上で読める濃藍 #1e2d52。著者名は地絵の家の中心（幅の約45%）に合わせて下部に置く。ロゴは公式ロゴの線画（藍）を小口側の上に置く（表紙幅の約7%、周囲の余白はロゴ幅の1/8以上＝LOGO.md の規定）。地絵には文字もロゴも描き込まない（生成時のゾーンルール：題字ゾーン右上・著者ゾーン下部中央・ロゴゾーン小口上は地絵で空けておく）。入口は「耳で読む」「目で読む」の2ボタンだけ（表紙タップでは開かない）。ボタンの補足文は「朗読つき／朗読なし」固定（v1.13.3 で整理。以前はしおりがある間「・つづきから（第N章）」を補足文に混ぜていた）。しおりがあるときは、ボタン上の小行（#coverResume）に「つづきから（第N章）」を別に示す（どちらの入口でも同じ章から再開するので行は1つ）。初めて読むとき（しおり無し）は、どちらの入口からもまず目次ページを開く（v1.12.4）。
- **目次**：紙の面に縦書きの柱。本文・扉と同じ帯（再生・家マーク・ノンブル）を持ち、「戻る」のような画面専用ボタンは置かない（開いた元への帰りは後方操作に統合、v1.12.4）。レイアウトは A案（次項）。
- **扉**：タイトルブロック（章番号・題・語り手）をひとかたまりとして中央に組む。案内文言なし。
- **本文**：柱（章題）＋帯（再生・家マーク・ノンブル）。ページ送りはスワイプのみ（タップではめくらない。v1.13.6〜）、メニューは帯のボタンからのみ開く（本文タップでメニューは開かない）。章背景は生成イラストから切り分けた**下帯のみ**（上帯は v1.13.4 で廃止。中央の本文域は紙のまま空ける）。**下帯の寸法ルール（v1.13.7 で数値化、v1.13.8 で改定。全章・今後の本にも適用する）**：帯全体はページ高さの最大23%まで。絵の本体（線・面のある部分）は最下部の15%以内に収め、帯の上の8%分は紙へ溶けるフェード専用とする。本文の表示域は下限をページ高さの85%までとし、本体と本文は重ならない（本文の行が掛かってよいのはフェード部まで。本体に文字が掛かる切り位置は不可）。ノンブルだけは例外として、従来どおり下の帯の中に置いてよい。改定の理由：初版（帯30%・本体22%・本文下限78%）では本文の終わる位置と絵の間に空白の帯ができ、ページが空いて見えた（第4章で顕著だったという実機感想）。本文域を広げ、絵の本体を最下部に寄せることで、空白の帯を残さない寸法にした。切り位置はこの範囲内で章ごとにモチーフを切らない位置で決める（生成手順と章ごとの指定は `work/split-bg-bands.py`）。旧線画 SVG は参照を外して残す（ロールバック用）。アニメーション層（雨など）は帯の上に重ね、「背景イメージ」オフでは帯ごと消える。
- **メニュー**：見出しは金茶の小ラベル＋細い罫線。行は全行同じ体裁（ラベル＋右端の操作）、薄い区切り線、行の高さ 42px〜。パネル下端はフェードでスクロールを示唆する。閉じるは楕円ピルにせず、右上の×印の線画アイコン（帯のアイコンと同じトーン、44px）。文字サイズはピル型トグルにせず、「標準／大」の文字の選択肢を行の中に並べ、選択中を藍で示す（v1.13.2、形の統一）。**分類は全画面で 音／表示／再生 の3つに固定**する（v1.13.3 で再編。旧「耳で読む」の設定／「目で読む」の設定というモード別見出しは廃止——全設定は両モード共通という実態に見せ方を合わせた）。割り当ては、音＝ページめくり音・BGM／表示＝文字サイズ・フリガナ・朗読中の文を強調・背景イメージ・画面を暗くしない／再生＝再生速度・バックグラウンド再生（「朗読中の文を強調」は文の見た目の設定なので表示に置く）。目で読むでは朗読に紐づく行（再生速度・バックグラウンド再生・朗読中の文を強調）を隠し、行が無くなる「再生」の見出しも一緒に隠す。再生速度も文字サイズと同じ文字の選択肢の並びにする（巡回式の楕円ピルは廃止。候補は 0.8／1.0／1.25／1.5／2.0 で、0.75 は含めない）。項目が1つだけの見出しグループは作らない（旧「設定」グループはインストール案内1件のみだったため廃止し、案内はナビゲーションのグループへ統合）。ナビゲーションの項目順は本の並び順（表紙に戻る→目次を開く）で、ナビ行には見出しを付けない。
- **奥付**：本文の最終ページの次に、独立した1ページとして置く（ページ内の帯にしない）。帯は他のページと共通のものを付け、**右下＝家マークのみ出す**（再生は朗読対象が無いので出さない。片方が無くても家マークの位置は動かさない）。「表紙に戻る」の文字リンクは置かない（v1.12.4 で廃止）。ページ操作（スワイプ）は他のページと共通に効かせ、前へ＝本文の最終ページ、次へ＝表紙とする。耳／目どちらのモードでも奥付の見た目は同じ（再生なし・家のみ）。

### 4. 目次の A案（v1.12.4 で確定）

- 各項目（章番号＋タイトル）を1本の柱として扱い、**全項目の上端を完全に揃える**（`justify-content: flex-start`）。
- 柱の頭の位置は `--toc-top: 27dvh`（シートの上から約1/3、少し上気味。下の余白を広めに取る）。
- 項目の背丈は `--toc-item-h: 232px` に統一（一番長い第七章の題が自然に占める高さに合わせた実測値）。現在地の印（背景色）の領域は、題の長さで変わらない。
- 2枚目以降の目次ページも同じ規則。見出し（「目次」）の柱も同じ頭の位置から始める。

### 5. 数値で固定している約束（自動テスト側）

E2E（`e2e/app.spec.ts`）で固定しているもの：

- アイコンの位置が全画面・全モードで統一（左下＝再生、右下＝家マーク。目で読むでは再生だけ消えて家は動かない）
- 帯の家具が全画面（本文・扉・目次・奥付）で同じ寸法（44px）・同じ色・同じ浮き（`--band-lift` 10px）であること（v1.12.5）
- 扉と目次の枠が本文と一致する、目次の項目の上端・高さの一致と頭の位置（約1/3）
- ノンブルの体裁と帯の中央配置
- メニューの分類（見出しは 音／表示／再生 の3つで、行の所属は分類どおり。目で読むでは「再生」の見出しごと朗読に紐づく行が消える）と、再生速度の選択肢の候補（0.8／1.0／1.25／1.5／2.0）と選択状態の示し方（藍＋aria-pressed）（v1.13.3）

静的チェック（`scripts/check-dist.mjs`、verify に含まれる）で固定しているもの：

- 帯を持つ全画面が共通クラス（`.sheet-footer` / `.page-footer` と `.page-icon-btn`）で帯を構成していること。画面専用の帯・部品を作ると落ちる（v1.12.5）
- 廃止した画面専用部品（`.toc-back` / `.toc-pager` / 奥付の文字リンク）が成果物に残っていないこと
- 全章の音声が precache 上限（`maximumFileSizeToCacheInBytes`）以下で、sw.js の precache に全て入っていること（v1.13.0）。あわせて `scripts/content-checks.mjs` が、初回案内の表示容量（`totalAudioBytes`）と実ファイルの一致を固定する

人の目（監査と実機確認）に残るもの：

- 世界観との一致、上品さ・静けさのような印象
- 実機（iPhone）での安全領域・ぼやけ・操作感
